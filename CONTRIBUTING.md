# CONTRIBUTING — контракты и пайплайны appboo

Термины по RFC 2119: **MUST** — минимум, без которого приложение не работает;
**SHOULD** — строгий целевой вид, к которому приводит нормализатор; **MAY** —
допустимые варианты. Временное несоблюдение SHOULD — не баг: плеер и скрипты
приводят приложение к целевому виду постепенно.

Единственный механизм обнаружения приложений — манифесты (`apps.json`,
`meta.json`). Плеер ничего не сканирует и не угадывает: что объявлено — то и
грузится. Строгость обеспечивают скрипты (`scripts/validate.mjs`,
`scripts/normalize.mjs`), а не плеер.

## Термины

- **Плеер** — `index.html` в корне appboo: каталог, фильтры, темы, отдельная
  страница приложения, просмотр скриншотов, окно приложения.
- **Приложение** — мини-приложение в `apps/<папка>/`.
- **Реестр** — `apps.json` в корне: массив имён папок, порядок «старые → новые»
  (плеер показывает новые сверху).
- **meta/** — папка листинга приложения: данные для карточки плеера, иконка,
  скриншоты.
- **Страница приложения** — отдельный экран плеера с полными данными
  приложения, скриншотами и кнопками. Открывается кликом по карточке или
  прямой ссылкой `#/app/<имя папки>`; единственный вход в просмотр скриншотов.

Обычно плеер менять запрещено: правки допустимы только в пределах путей
загрузки (реестр / meta / иконки / вход приложения), текста ошибки загрузки,
мягкого парса JSON, обложки карточки (скриншоты, точки, свайп) и бейджей
языков. Фильтры, поиск, сортировки, темы (Системная / Тёмная / Светлая), окно
настроек, карточки, страница приложения, просмотр скриншотов, окно приложения,
копи-ссылка, скролл-кнопки — не трогать. Внешние библиотеки в плеер не
добавляются (devDependencies — только в `scripts/`).

## Структура

```
appboo/
├── index.html                  # плеер
├── manifest.webmanifest        # PWA-манифест плеера (не трогать)
├── appboo-icon.svg
├── apps.json                   # реестр: массив имён папок, старые → новые
├── README.md
├── CONTRIBUTING.md             # этот документ
├── docs/
│   └── meta.template.json      # шаблон метаданных (строгий JSON)
├── scripts/
│   ├── validate.mjs
│   └── normalize.mjs
└── apps/
    └── <app>/
        ├── src/                # только код приложения
        │   ├── index.html      # точка входа (MUST)
        │   └── ...             # любые файлы/папки приложения
        └── meta/               # листинг для плеера (опционально)
            ├── meta.json
            ├── icon.svg
            └── screenshots/
                ├── screenshot-1.webp
                └── screenshot-2.webp
```

## Контракт приложения

### MUST (минимальный дроп)

1. Папка в `apps/` с уникальным именем.
2. `src/index.html` — точка входа.
3. Строка с именем папки в `apps.json`, добавляется в конец. Порядок реестра —
   «старые → новые», плеер показывает новые сверху.

### SHOULD (строгий вид)

- `meta/meta.json` со всеми полями (таблица ниже).
- `meta/icon.svg` — монохромный штриховой SVG с явным цветом штриха.
- Точные `languages` (коды ISO 639-1, нижний регистр).
- Ровно 2 скриншота: `meta/screenshots/screenshot-1.webp`,
  `screenshot-2.webp` — 1280×800, ≤300 КБ, WebP q≈85 (пиксель-арт — lossless),
  объявленные в массиве `screenshots`.
- Строка в README-каталоге (между маркерами `<!-- catalog:start -->` /
  `<!-- catalog:end -->`; перегенерируется нормализатором).
- Имена новых папок — kebab-case: `^[a-z0-9]+(-[a-z0-9]+)*$`. Легаси-имена не
  переименовываем.

### MAY

- `info`, `color`, `ai`, `tags` — любые значения в допусках таблицы;
  неизвестные поля meta.json игнорируются плеером.
- Скриншоты во временных форматах (jpg/png) — допустимо на переходный период,
  главное объявить их в `meta.json`; нормализатор с `--convert` доведёт до WebP.
- Папки приложения внутри `src/` — любая структура (assets, js-модули и пр.),
  если точка входа — `src/index.html`.

## Поля meta.json

Все пути — относительно папки `meta/`. Все поля опциональны; полный шаблон —
`docs/meta.template.json`.

| Поле | Тип / допуски | Дефолт/фолбэк |
|---|---|---|
| `title` | string | имя папки |
| `description` | string | `""` |
| `info` | string | `""` |
| `icon` | string: путь к файлу / emoji / буква / URL / data-URI | первая буква title |
| `color` | string `#RRGGBB` | автогенерация из title |
| `ai` | string | `""` |
| `platform` | `desktop` \| `mobile` \| `both` | `""` |
| `tags` | string[] | `[]` |
| `languages` | string[], ISO 639-1, lowercase | `["ru"]` (на стороне плеера) |
| `screenshots` | string[], пути в порядке показа | `[]` |

## Терпимость плеера

Плеер — tolerant reader: принимает всё из этого списка, никогда не падает на
кривых данных, молча использует дефолты. Чинить эту терпимость в будущих
задачах запрещено.

- `meta/` и `meta.json` могут отсутствовать целиком; поля — частично;
  неизвестные поля игнорируются. Битый JSON одного приложения не роняет каталог.
- `icon`: emoji, буква, файл svg/png/webp/jpg, внешний URL, data-URI — как
  сейчас, не регрессировать. SVG по-прежнему рисуется через CSS-mask с
  перекраской в цвет темы. Нет meta.json или пустой `icon` → буква из title.
- `screenshots`: показываются только объявленные в `meta.json`. Формат любой
  (webp/jpg/jpeg/png и пр. — плеер не проверяет расширения, целевой вид —
  WebP). Битая/недоступная запись массива → слайд пропускается; все битые →
  иконка.
- Мягкий парс JSON (`apps.json`, `meta.json`): при ошибке `JSON.parse` повторить
  после удаления комментариев `//`, `/* */`, `#` и висячих запятых — с учётом
  строковых литералов (не резать `//` внутри URL). Не помогло → текущее
  поведение (экран ошибки / дефолты meta). Реестр: trim записей, отбросить
  не-строки, пустые и дубликаты.
- Шаблон и файлы после нормализации — строгий JSON без комментариев;
  комментарии прощаются только в рукописных файлах.
- JS-ошибок в консоли быть не должно.

## Гайд иконки

- Формат — монохромный штриховой SVG: единый `viewBox="0 0 24 24"`,
  `fill="none"`, `stroke-width="1.7"`, `stroke-linecap="round"`,
  `stroke-linejoin="round"` — как у большинства существующих иконок
  (сверяйтесь с ними же как с примерами).
- Явный цвет штриха обязателен (`stroke="#ffffff"` у существующих), но его
  значение не важно: маска плеера использует только альфа-канал SVG и
  перекрашивает иконку в цвет темы.
- Путь к иконке в `meta.json` — просто `"icon.svg"` (файл в `meta/`).
- Легаси-исключения (градиентные и многоцветные иконки, `icon.png`) остаются
  как есть; новые иконки — строго в общем стиле.

## Пайплайны

### Быстрый дроп

Минимум, чтобы приложение появилось в каталоге:

1. `apps/<имя>/src/index.html` — папка и точка входа.
2. Строка `<имя>` в конец `apps.json`.
3. Остальное (meta, иконка, скриншоты, README) — потом; плеер покажет карточку
   с буквой из названия и бейджем `ru`.

### Строгая установка

Полный вид за один заход:

1. Папка `apps/<имя>/` (kebab-case), входной файл при необходимости
   переименовать в `src/index.html`.
2. `meta/meta.json` по `docs/meta.template.json` — все поля.
3. `meta/icon.svg` в общем стиле (см. гайд выше).
4. 2 скриншота `meta/screenshots/screenshot-1.webp` и `screenshot-2.webp`
   (1280×800, ≤300 КБ, WebP q≈85; пиксель-арт — lossless) и пути в
   `screenshots`.
5. Строка в README-каталоге (или прогон нормализатора — он впишет сам).
6. `npm run validate` — MUST зелёные.

### Удаление приложения

1. Удалить папку `apps/<имя>/`.
2. Убрать строку из `apps.json`.
3. Убрать строку из README-каталога (или прогнать нормализатор).
4. Проверить отсутствие ссылок: `grep -rn "<имя>" --include="*.html"
   --include="*.md" --include="*.json"` — старые прямые ссылки на страницу
   приложения ломаются молча, заглушек нет.

### Нормализация

Приведение репозитория к целевому виду и поддержание его:

1. `npm run validate` — посмотреть MUST/долги.
2. `node scripts/normalize.mjs --dry-run` — план без изменений.
3. `node scripts/normalize.mjs` — выполнение (флаг `--convert` конвертирует
   скриншоты в WebP через `sharp`, `--lossless` — без потерь, для пиксель-арта;
   `sharp` — опциональная devDependency, `npm i`).
4. Просмотреть `git diff` и закоммитить. Повторный запуск нормализатора без
   изменений даёт пустой diff.

## Скриншоты

По 2 на приложение: (1) стартовое состояние, (2) характерная сцена/фича.
Viewport 1280×800; мобильные приложения — по центру ландшафтного холста.
Допускается Playwright-скрипт. jpg/png временно ок — главное объявить их в
`meta.json`; нормализатор потом доведёт до WebP (`--convert`).
